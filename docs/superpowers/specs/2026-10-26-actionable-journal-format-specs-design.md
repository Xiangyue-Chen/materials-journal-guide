# 期刊投稿硬参数速查设计

## 意图

当前页面虽然列出了官方要求，但信息分散，用户仍不能快速回答“摘要写多少、正文怎么排、主图放几幅、分图用大写还是小写、参考文献怎么引”。本次改动把这些决定写作和排版的参数放到期刊工作台第一屏。

## 目标

- 17 本期刊均提供统一的六项速查：摘要、正文骨架、图表数量、分图标注、图注、参考文献。
- 每项同时显示“官方规则”和“怎么执行”，并附可点击来源。
- 官方未设固定值时明确写“官网未规定固定上限”，本站建议仍给出可执行的字数、图数或组织方式。
- 在速查表后提供按顺序排列的“推荐排稿骨架”，说明每个部分承担什么任务。
- 保留现有官方要求、模板实例和选刊建议，不再加入示意图或虚构论文截图。

## 非目标

- 不把本站建议描述为期刊强制要求。
- 不保证不同稿件类型共享相同上限；页面始终显示默认文章类型。
- 不承诺影响因子、分区、审稿时长或接收率等易变数据。
- 不迁移现有 GitHub 与 Streamlit 部署方式。

## 方案

考虑过三种方式：继续扩充现有长表、把全部内容压成一张横向比较表、单独建立结构化速查层。选择第三种：新建 `journal_format_specs.yaml`，由独立加载器校验，再在现有工作台最前面渲染。这样既能把硬参数放在第一屏，也不会让已有的官方要求数据继续膨胀；比较页和后续导出也能复用结构化字段。

## 数据与证据边界

每本期刊含六个固定字段：

- `abstract`
- `manuscript_structure`
- `display_items`
- `panel_labels`
- `figure_legends`
- `references`

每个字段包含：`official`、`advice`、`scope`、`source_url`。`scope` 只能是“官方硬性”“官方惯例”“官网未规定固定上限”“本站建议”。其中 `official` 只写官方页面能支持的内容；若官网没有稳定上限，必须明确写“官网未规定固定上限”，不能写“需复核”“见官网”等空占位。`advice` 始终给出材料/高熵合金论文可直接采用的执行办法，但显示为“本站建议”。

每本期刊另含 `blueprint`，按稿件顺序列出部分名称与任务。蓝图是写作建议，不冒充官方章节强制顺序；官方明确规定章节顺序时，在对应的 `manuscript_structure.official` 中单独说明。

## 界面

选择期刊后依次显示：

1. “投稿硬参数速查”：六行三列，分别为项目、官方规则、怎么执行。每行带证据标签和官方来源链接。
2. “推荐排稿骨架”：编号列表，显示章节名称、目标和建议篇幅/图号安排。
3. 原有“官方要求总览”“稿件各部分格式”“提交文件与技术规格”“官方模板与实例”。
4. 原有选刊契合度建议折叠区。

移动端表格可能过宽，因此速查区使用两列卡片而非 DataFrame；每张卡片保持短段落和明确标签。

## 验收标准

- 17 本期刊全部通过结构与来源校验。
- 第一屏能直接看到上述六项信息，不需要先展开折叠区。
- Nature、Nature Materials、Nature Communications、Communications Materials、Advanced Materials、PNAS 的已核验精确值与字母大小写被自动化测试锁定。
- 官网未给固定上限的项目仍含具体本站建议，并且不会显示“需投稿前复核”“按指南执行”“具体见官网”。
- 全量测试、Streamlit 启动检查和线上页面检查通过。
