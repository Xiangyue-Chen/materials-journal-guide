# 金属材料期刊要求查询与对比网站设计

## 1. 目标

建立一个独立 GitHub 仓库和可在线访问的网页，集中整理金属材料、高熵合金和结构材料研究常投期刊的官方投稿要求。用户可以按投稿梯队、出版社、开放获取模式和研究方向筛选期刊，并将最多 4 本期刊并排比较。

首版只做“期刊要求查询与对比”，不做命中概率预测、自动选刊、论文内容审查或非官方审稿周期众包。

## 2. 目标用户与核心任务

目标用户是准备投稿金属材料、高熵合金、合金设计、力学性能、腐蚀与加工研究的科研人员。

核心任务：

1. 从“正刊 → 大子刊 → 小子刊 → 材料综合旗舰刊 → 金属材料专业期刊”逐级浏览。
2. 快速查看选题范围、文章类型、初投格式、篇幅与摘要限制、图表/图文摘要、参考文献、数据政策、开放获取和审稿模式。
3. 选择 2–4 本期刊并排比较差异。
4. 从每一项摘要直接跳转到期刊官网核对，并看到最近核验日期。

## 3. 首版期刊范围

投稿梯队是便于使用的导航分类，不宣称是官方排名或严格学术等级。

- 正刊：Nature、Science。
- 大子刊：Nature Materials、Nature Communications、Science Advances。
- 小子刊：Communications Materials。
- 材料综合旗舰刊：Advanced Materials、Materials Today、PNAS。
- 金属材料核心刊：Acta Materialia、Scripta Materialia、Materials Science and Engineering A、Journal of Materials Science & Technology、Journal of Alloys and Compounds、Materials & Design、Intermetallics、Corrosion Science。

后续可沿相同数据结构加入 International Journal of Plasticity、Metallurgical and Materials Transactions A、Additive Manufacturing 等期刊。

## 4. 方案比较与选择

### 方案 A：静态表格页面

开发最少，但筛选和对比能力弱，扩刊后维护困难。

### 方案 B：实时自动抓取出版社网页

表面上更新及时，但出版社页面结构变化频繁，字段含义因文章类型不同，容易把页面文本误解析为硬性要求。

### 方案 C：经人工核验的结构化数据库 + 网页（采用）

期刊信息保存在 YAML 中，网页动态读取；每本期刊保留官网、作者指南、字段状态和核验日期。官网未明确的信息显示“投稿前复核”，不由程序猜测。该方案在可维护性、可信度和开发成本之间最平衡。

## 5. 数据与证据规则

每条期刊记录包含：

- 基本信息：名称、缩写、出版社、投稿梯队、研究方向标签。
- 投稿信息：主要文章类型、初投稿件形式、摘要/篇幅说明、图文摘要、Highlights、参考文献、图像要求。
- 政策信息：数据可用性、开放获取模式、同行评审模式、特殊声明。
- 溯源信息：官网、作者指南、补充来源、最近核验日期、记录状态。

证据边界：

- 只把官方期刊或出版社页面作为硬性要求来源。
- 影响因子和分区首版不写入固定数值；未来加入时必须包含统计年度和数据来源。
- 审稿速度仅展示期刊官网公布的指标，并明确口径；官网没有时显示“官方未公布”。
- APC 不写死易过时金额，优先链接官方费用页并显示 OA 模式。
- 同一期刊不同文章类型的限制不强行合并；首版以原创研究论文为主，并提示用户提交前按文章类型复核。

## 6. 页面结构

### 首页

- 简短说明、数据覆盖数、最近核验日期。
- 搜索框和筛选器：投稿梯队、出版社、研究方向、OA 模式。
- 期刊卡片：定位、适配方向、关键格式、官网入口、加入对比。

### 对比区

- 最多选择 4 本期刊。
- 按字段逐行对比，差异清晰可见。
- 对过期记录和“投稿前复核”字段显著提醒。

### 数据说明

- 解释投稿梯队不是排名。
- 解释数据来源、核验日期和更新方式。
- 提供 GitHub 数据文件入口，方便提交更正。

## 7. 视觉与交互

采用克制的学术编辑风格：暖白背景、深石墨文字、矿物蓝绿强调色和少量金色提示。使用大标题、紧凑筛选区、卡片式结果和横向对比表；移动端退化为纵向信息块。避免装饰性科学图库，重点突出可读性和证据来源。

## 8. 技术架构

- Python 3.11+
- Streamlit
- PyYAML 数据加载
- pytest 数据结构与筛选逻辑测试
- GitHub 仓库保存代码和数据
- Streamlit Community Cloud 在线部署

代码分层：

- `data/journals.yaml`：唯一正式数据源。
- `journal_guide/data.py`：加载、校验和标准化。
- `journal_guide/filters.py`：搜索、筛选和比较选择逻辑。
- `app.py`：Streamlit 页面与展示。
- `tests/`：数据质量和核心逻辑测试。

## 9. 验收标准

1. 首版包含上述 17 本期刊，且每本都有官方主页、作者指南和核验日期。
2. 可以按关键词、梯队、出版社、方向和 OA 模式组合筛选。
3. 可以选择 2–4 本期刊并排比较；少于 2 本时给出友好提示。
4. 未明确字段不会显示为确定事实。
5. 页面在桌面和手机宽度下均可使用。
6. 数据校验、筛选和比较测试通过，Streamlit 应用能够无交互启动。
7. README 说明本地运行、数据维护、证据边界和部署方式。
